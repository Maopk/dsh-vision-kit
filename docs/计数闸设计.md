## 2 建议的闸：`tools/check-counts.py`（三查）

命名沿用另一个仓库（`dsh-termux-kit`）已有的 `tools/check-counts` 传统，便于两个仓库对读；
但**判据不同**：那边的口径是"本机预期红 + 基线比对"，这边**目标全绿**。

### 查 1 · 计数单一化（踩坑条数）
- **真源解析**：在 `actor/README.md` 的 `## 踩过的坑` 段内取 `^([0-9]+)\. ` 的行数 ⇒ N。
- **断言**：`README.md` / `README.zh-CN.md` / `skills/*/SKILL.md` 里所有"数字 + pitfall/踩坑"提法都 = N。
  正则要同时覆盖**英文数词**（`eleven` …）、**中文数字**（`十一` …）与**阿拉伯数字**。
- **失败输出**（照 `check-no-secrets.sh` 的形态，逐处给行号）：
  `pitfalls: source 11 | README.md:93 says eleven ✔ | README.zh-CN.md:83 says 十一条 ✔ | <file>:<line> says 九 ✘`

### 查 2 · 双语数字一致性（本轮真凶）
- **做法**：抽两份 README **非代码块**行里的数字 token（把 `0.62–0.72` 这类范围当整体），比较两个集合。
- **判据**：`仅 EN = ∅`（EN 是权威，EN 有的 ZH 必须也有）；`仅 ZH ⊆ allowlist`。
- **allowlist（今天的内容，含理由）**：`2.1346` / `100` / `107.17` —— `README.zh-CN.md:232` 的
  tesseract 行直接引了读出来的文本「本月预算 ¥2.1346 / ¥100 余额 ¥107.17」，而 EN 行只写
  "reads it with no preprocessing"。**每条 allowlist 必须带理由字符串**，新增要在 PR 里说明。
- **同一对检查再跑一次报告**：`docs/vision-capability-report.md` ↔ `docs/视觉能力实测报告.md`。
- **今日实测（原型，2026-10-06）**：修完 ZH 后 `仅 EN = {}`（空集）、`仅 ZH = {2.1346, 100, 107.17}`
  ⇒ **加 allowlist 后即绿**；修之前它会把 `48 / 102 / 83 / 0.72 / 0.30 / 0.22 / 2.6 / 95 / 1371` 全部报成"仅 EN"。

### 查 3 · 清单完整性
- **真源 = 磁盘**（`tools/*.py`、`tools/*.ps1`、`docs/*.md`）。
- **断言 A**：Layout 块里列出的每个文件名都**存在**（防止改名/删除后文档悬空）—— 今天 = 0 命中。
- **断言 B**（只报告，不判失败）：磁盘上存在、Layout 块没列的文件 —— 今天是 3 个自检工具。
  两种收尾：① 在 Layout 块加一行（例如 `repo self-check tooling: ci-static.ps1 / check-skill-ops.py /
  install-skills.ps1`）；② 把这 3 个名字放进 allowlist。**推荐 ①** —— 否则读者看到的 `tools/` 是残缺的。

## 4 边界（明确不做的部分）

- **不动 CHANGELOG 的历史条目**：`CHANGELOG.md:153`（seven/nine）与 `:19`（"(23)"）记的就是当时的状态
  ⇒ 闸只查"当前文档"；`CHANGELOG.md` 与 `docs/界面自动化日志.md` 进**历史白名单**。
- **不改 EN**（EN 是权威）；查 2 只报差异，**不自动改写 ZH**。
- **不做"自动同步 ZH"**：生成翻译是另一件事（要模型），不属于闸的职责。
- 查 3 只断言"列出的存在"，不要求"存在的一定列出"（后者要 allowlist，见查 3 的两种收尾）。
- 不引入依赖、不联网、不产截图（照 `CONTRIBUTING.md` 的 Ground rule 4）。

## 5 落地步骤（下次改 vision-kit 时照做）

1. 写 `tools/check-counts.py`（约 120–150 行，标准库）。
2. 本地跑：期望 `exit 0`（今天的基线）；再自证三条红线（临时改一个数字/条数，确认它红）。
3. `tools/ci-static.ps1` 加第 7 阶段，照第 6 阶段的形态（打印检查名、失败即 `exit 1`）。
4. `CONTRIBUTING.md`：`## Running the checks` 加一条命令；`## Where each script is checked` 加一行。
5. `CHANGELOG.md` `### Added` 一条（写清它抓到的第一类漂移 = 踩坑条数 / 双语数字）。
6. 可选加强：把查 2 扩到"报告对"与 `skills/*/SKILL.md` 里引用的数字（真源 = 报告里的表）。

## 6 为什么值得（证据）

- 这次的 ZH 落后**不是翻译质量问题，而是"没有任何东西会红"**：`41 / 110 / 91 ms` 在仓库里活过了
  至少一个版本周期（`CHANGELOG.md:151-153` 记着 EN 早就改过，ZH 没跟上），而且**先看到错的那份的人
  恰好是读中文的人**。
- 仓库自己的 Ground rule 1（"每个几何声明都要有数字"）和总纲 §4(h)（计数只写一处 + 带复核命令）
  在**文档**层面同样适用：op 数已经这么做了（`check-skill-ops.py`），踩坑条数没有。
- 成本：一次 CI 红 ≈ 一轮修 + 一次重发；而查 2 是纯本地字符串比较（毫秒级）。
