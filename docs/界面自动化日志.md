# 界面自动化日志：脚本驱动真实桌面 GUI（挂件表演 / QQ 代发 / 识别提速）

> English abstract: this is the Chinese work log for driving a real Windows desktop
> GUI from scripts instead of the DOM: (1) dragging a web widget along a measured
> heart path with pixel-level evidence, (2) sending a QQ message and proving it with
> three independent signals, (3) cutting contact recognition from ~0.7 s of OCR to
> ~5 ms of in-process template matching (whole flow 1.89 s in a single call).
> No screenshots are published — UI captures would expose conversation content.

所有数字都是**当场实测**，不是估算。本仓库不含任何界面截图。

## 摘要

| 目标 | 结果 |

| 在挂件上连点三下并证明点击生效 | 点击前后同区域平均差 ~210（全屏 1.18% 像素变化）→ 弹出余额气泡 |
| 代发一条 QQ 消息 | 成功；**三条独立证据**（OCR conf 94.9 / 新增时间分隔线 / 输入框清空 + 气泡蓝像素 7.2%） |

## 1 工具链

| 文件 | 作用 |
|---|---|
| `tools/gui-steps.ps1` | 手：JSON 计划驱动的鼠标/键盘/剪贴板/截屏/模板匹配引擎，**整个交互跑在一个 pwsh 进程里** |
| `tools/contact-send.ps1` | 一条命令 = 搜索联系人 → 选中 → 用模板确认真身 → 发送 → 像素复核（`-DryRun` 只粘贴不发送） |
| `tools/pixel-verdict.py` | 廉价的"眼睛"：输入框墨迹 + 气泡蓝色像素两个判据，给出 PASS/FAIL，不调用 OCR |
| `tools/ocr_boxes.py` | tesseract TSV 包装：裁剪/放大/psm/反相，输出**原图坐标**下的行框与中心 |
| `tools/brightmap.py` | 区域亮度 ASCII 热力图，用来找面板与按钮边界 |

设计取舍：坐标、热键、进程名都是**站点相关的常量**（本例：QQ 9.9.21、2560×1600、Ctrl+Enter）。脚本本身不做"看"，只做"比"——看图发生在人写脚本的时候。

## 2 案例一：把挂件沿心形拖一圈（像素级取证）

- 定位方法（每步现拍）：原生截屏 → 饱和度掩膜（`max-min>45` 且 `max>60`）→ 8× 降采样 → 连通域 → 取最大彩色块的中心为抓取点，保证落进 alpha>10 的可命中区域。
- 逐帧实测（光标与挂件距离 = 抓取偏移）：r1 (1372,352) r2 (1580,448) r3 (1496,792) r4 (1308,1064) r5 (1284,1088) r6 (1116,832) r7 (996,488) r8 (1188,332)，与光标距离稳定 **34–39 px**，全程没有松脱，连线闭合即心形。
- 松手行为：**不会自己飘回锚点**——画完停在屏幕中央，直到再次被抓住；只有窗口尺寸/布局变化才重新套用保存的锚点。
- 吸附/翻转：贴左边时艺术图水平镜像（命中测试 `lx = 610 - lx`），拖拽姿态与静止姿态尺寸不同（静止 208×184，拖拽 216×160 / 280×168），所以模板匹配置信度会从 0.955 掉到 ~0.55 —— 因此全程不用固定模板，改用颜色块定位。
- 点击生效判定：连点三下后，与点击前逐像素比较，`x128-320 / y1216-1312` 区域平均差 ~210（全屏 1.18% 像素变化）= 挂件上方弹出余额气泡。

## 3 案例二：代发一条 QQ 消息

环境：QQNT 9.9.21，2560×1600 满屏，右栏会话区 x≥620，输入框文字行 y≈1362–1390。

**阻塞 1：按回车没反应。** 脚本末尾打印 `foreground=G`（G = DSH 窗口标题）——按键落到了 DSH 而不是 QQ。DSH 自己的窗口会不断抢回前台，单独 `SetForegroundWindow`/`ShowWindow` 不够。
修法：`SetWindowPos(HWND_TOPMOST)` + `BringWindowToTop` 把目标窗口钉住，再点击/按键，收尾 `HWND_NOTOPMOST` 还原（`gui-steps.ps1` 的 `top` 步骤）。

**阻塞 2：发送键是 Ctrl+Enter**，单回车只换行。组合键要按下每键间隔 30 ms、按住 40 ms、抬起每键 25 ms 才稳（VK `0x11` + `0x0D`）。

**三条独立证据**（同一张发送后截屏）：

1. 气泡文字：裁切气泡、放大 4×、`--psm 7`、反相 → conf **94.9**（首尾字符是气泡边框）；
2. 消息区新增居中时间分隔线 `17:15`（发送前那张没有）；
3. 输入框那行草稿消失，同一带的颜色从 `(16,16,16)` 变成 QQ 送达气泡蓝 `(0,96,192)`，占该带 7.2%。

只发出一条（其上一条气泡是会话原有内容）；收尾解除置顶、光标复位。

## 4 案例三：把"识别 + 选择"压到毫秒

| 环节 | OCR 路线 | 现在 |
|---|---|---|
| 认出会话头（是不是本人） | tesseract **0.68–0.70 s/次** + 一轮判断往返 | **零均值归一化互相关（ZNCC）**，±6 px 抖动搜索，**≈5 ms** |
| 抓图 | 整屏 2560×1600 ≈ **0.25 s** | 只抓会话头 175×50（`CopyFromScreen`）≈ **5 ms** |
| 判别力 | "浊"稳定误读成 济/汲/沂/洼 | 正样本 **1.000 PASS**；故意错位 400 px → **0.336 FAIL**（阈值 0.80） |
| 等待 | 搜索 600 ms + 打开 700 ms | **200/250 ms**（实测 150/200 ms 也稳过） |
| 整链 | 十几分钟、几十次调用 | **1.89 s，一次调用** |

1.89 s 的去向：空 pwsh 启动 **0.40 s** + 脚本加载（预编译 `DshInput.dll` + `System.Drawing`）**0.05 s** + 置顶/取消置顶 0.4 s + 点击/粘贴/两次等待 ≈0.9 s + **识别 0.005 s**。

预编译：`Add-Type -TypeDefinition ... -OutputAssembly DshInput.dll` 一次，之后 `Add-Type -Path` 加载 —— csc 编译 ~0.5 s 变成加载 ~0.05 s。

## 5 踩坑清单

- **Add-Type 的 C# 里不能 `using System.Windows.Forms/System.Drawing`**（pwsh 7：`CS0234` 命名空间不存在 / `CS1069` 找不到 `Bitmap`）。办法：位图读取留在 PowerShell（`LockBits` + `Marshal.Copy`），只有 `byte[]` 算术进 C#（`Gray32` / `Zncc`）。
- 只为一个 `VirtualScreen` 加载整个 WinForms 不划算 → 改 `GetSystemMetrics(76..79)`。
- tesseract 读深色 UI 必须**紧裁 + scale 2–3 + psm 6/7**，否则整片乱码；中文昵称的"浊"稳定误读。
- 全屏截图会拍到 DSH 自己的窗口，容易把 DSH 的内容误当成目标应用的内容（本项目曾据此误判消息区）。
- `py_compile` 产生的 `__pycache__`、计划 JSON、截图都不要提交（见 `.gitignore`）。

## 6 复现

```powershell
$py = "python"          # 需要 numpy + Pillow
$work = "$env:USERPROFILE\gui-work"

# 1) 单步驱动（计划 JSON：focus/top/move/click/key/paste/match/sleep/shot）
pwsh -File tools\gui-steps.ps1 -PlanPath "$work\plan.json"

# 2) 一条命令完成"搜索联系人 → 选中 → 确认真身 → 发送 → 复核"
pwsh -File tools\contact-send.ps1 -Text "hello from a script" -Contact "someone"
pwsh -File tools\contact-send.ps1 -Text "probe" -DryRun        # 只粘贴+复核，不发送

# 3) 模板匹配的判别力自测（正/负样本）
pwsh -File tools\gui-steps.ps1 -PlanPath "$work\neg.json"      # 期望 FAIL
```

## 边界与隐私

- 仓库**不含界面截图**：截图会暴露会话内容。结论只以数值 + 复现命令给出。
- 联系人名以 `someone` / `<contact>` 代指；坐标是 2560×1600 实测值，换分辨率、主题或应用版本都要重测。
- 脚本用缓存坐标 + 模板匹配：布局变了会 **FAIL 而不是盲发**；"发错会话"要靠会话头模板匹配（`match` 步骤）来拦。
